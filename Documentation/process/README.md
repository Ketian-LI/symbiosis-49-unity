# Development process

Read the [development journal](../DEVELOPMENT_JOURNAL.md) for the sequence of decisions.
The [repository lineage](REPOSITORY_LINEAGE.md) identifies where each implementation lives.

## Follow a change

| Stage or problem | Decision | Read next |
| --- | --- | --- |
| Feeding prototype | Let placement of food affect animal responses | [Web history](history/early-web-history.csv) |
| Physical input and city planning | Explore tokens, previews and city routes | [Repository lineage](REPOSITORY_LINEAGE.md) |
| Room construction | Introduce the board through successive placements | [Journal](../DEVELOPMENT_JOURNAL.md) |
| Similar totals for different layouts | Review pairing rewards, penalties and trophy bands | [Balance and reading review](iterations/SKILL_GUIDED_UI_2026-11-21.md) |
| Results were hard to explain | Keep causes visible and highlight contributors | [Score-source record](iterations/SCORE_INDEX_2026-11-21.md) |
| Goals did not fit the page | Separate names, metric labels and progress | [Goal UI record](iterations/GOAL_PROGRESS_UI_2026-11-21.md) |
| Ethics review was missed | Disclose the oversight and the work still required | [Ethics reflection](../ETHICS_REFLECTION.md) |

A design request, a software fault and a participant finding are different reasons to revise a feature.
The journal identifies the available basis for each change.

[Iteration records](iterations/README.md) keep dated detail.
[Release notes](RELEASE_NOTES.md) identify source and download snapshots.
[History files](history/README.md) preserve the earlier records.
