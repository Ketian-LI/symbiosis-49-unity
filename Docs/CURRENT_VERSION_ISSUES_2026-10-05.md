# 当前版本问题与证据边界

基线：2026-10-05 本地 Unity 6000.3.4f1 工作区。以下是代码与已有脚本场景能支持的判断，不等于本次重新完成了整套 Unity 测试或参与者研究。

## 优先处理

1. **每日行动不一定产生新的空间取舍。** `GameRuntimeController.TodayAction` 接受挪房或成功投喂；`RoomLayoutEditorController` 只要求当前布局与上一布局真实不同。因此，把同一对房间来回交换也能逐日过关。README 记录过特定开局下反复交换仍长期存活的隔离诊断。这说明“必须操作”目前是有效输入门槛，不是有意义决策的证明。需要设计不会奖励机械往返、但也不强制无意义搬动的每日局势或评估方式。
2. **食物可达提示与实际进食仍有语义差距。** `AnimalNeedsController.EvaluateFoodAccess` 按当前份数、物种、栖地与通道匹配可达食物；动物仍须真正走到食物并取得份数。到达时间、其他动物占用、路线事件或捕食都可能改变结果。三格条的红绿表示当前可达性估计，不能被解释成“今天一定吃到”。规划预览另有次日种子与理论覆盖上限，更不能与实际餐数混用。需在试玩中检查玩家是否理解这几层信息。
3. **长期可玩性尚未确立。** 现有 PlayMode 场景验证部分前期策略及规则路径；README 中既有早期饥饿失败，也有单对房间往返仍存活较久的诊断。脚本策略不是玩家策略分布，更不能证明每日都有多样决策。优先测试“始终救急”“只顾通勤”“兼顾动物”三类真实或脚本策略，并记录每次调整的理由与后果。

## 完成边界与待验证项

4. **研究日志不等于研究结论。** 无摄像头 Research 模式能导出布局、指标和事件，但日志无法说明参与者是否理解“空间改变如何影响动物”或是否形成对责任的思考。需要把实际操作、游戏后果、参与者解释和反例对应起来，再写论文结论。
5. **实体识别还不是可用的完整输入方式。** 摄像头分支有校准、透视映射、49 模块校验和合成观测测试，但没有从原始画面稳定识别每个实体模块的最终检测器，也没有用最终棋盘、光照和相机位置验证。详见 `PHYSICAL_BOARD_RECOGNITION.md`。无摄像头研究版本不应借此宣称实体交互已完成。
6. **房间类型变换仍是未来方案。** 每日行动枚举预留 `Transform`，但当前没有可操作的房间类型变换系统；GDD 将其排除在已实现操作之外。若以后加入，需同时核对路线、食物、存档和每日互斥规则。

本次 GitHub 同步保存的是开发快照，不是已经通过完整试玩和研究验证的正式发行版。Unity 编辑器正占用该工程时，不应再启动另一个批处理编辑器来声称完成了最新全量测试。
