# 实体棋盘识别：当前接口与下一步

当前实现仅属于摄像头沙盒版本；无摄像头版本及 Research 模式不受影响。不能将其称为“已完成实体识别”。

## 已实现

- 摄像头预览、校准界面、49 间单格房／49 格合法性校验和稳定后更新布局的框架。
- `PhysicalBoardImageCalibration` 用棋盘外边界的四角像素坐标建立透视映射。四角顺序必须是左上、右上、右下、左下，坐标原点为图像左上。
- `PhysicalBoardProjectionModel.TryMap` 接收每间房的唯一 ID、**房间中心**像素坐标，以及指向房间印刷“上方”的像素坐标，输出 0–6 的列／行和 0–3 的四向旋转。标记若不在房间中心，检测器必须按已知偏移换算出房间中心。
- 映射失败、重复 ID、越界、靠近格线或方向不明时拒绝该帧；失效／过期的观测不应继续累积 1.5 秒稳定确认。
- 透视变换和 49 房布局已用合成观测做自动化测试。

## 尚未实现／需要实体信息

1. 确定每块实体房间的唯一可见标记、尺寸、贴附位置和朝向标识，以及四个棋盘校准标记。现有代码未绑定 ArUco、AprilTag 或二维码等具体方案。
2. 接入原始摄像头帧检测器，把识别结果转换为上述四角和 49 个房间观测；处理遮挡、反光、错误 ID 和摄像头断连。
3. 用最终底板、实际相机高度、镜头和室内光照测量中心／旋转误差与误识率，并验证频繁移动时的暂停和稳定确认。
4. 对齐摄像头版本与“每日只能进行一种行动”的新规则；目前物理布局自动更新不应被视为已验证的日行动计数。

任何摄像头参与的正式研究记录／参与者采集，都应先核对现行伦理审批和告知范围。
