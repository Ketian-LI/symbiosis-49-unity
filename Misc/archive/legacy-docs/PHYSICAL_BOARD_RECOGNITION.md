# 实体棋盘识别：当前状态与实机验收

桌游模式使用固定的 7 × 7 棋盘和 49 天建造规则；无尽模式不接收摄像头识别结果。当前程序已经有独立的 Python/OpenCV ArUco 识别器，并通过本机 `127.0.0.1:49549` 把房间观测传给 Unity。它不是自动建造：新增一块实体房间稳定识别约 1.5 秒后，Unity 显示建造预览，仍须由玩家确认。

## 已实现

- 四角定位码 ID 0–3、房间码 ID 10–89 的配置、识别器及打印文件，见 [摄像头识别说明](../../../Tools/CameraRecognition/README.md)。一局最多在 49 格中放置 49 块；80 块是物料库存。
- 使用四角定位建立透视映射，把可见房间码映射到 0–6 的列／行；重复编号、缺少四角码、越界或靠近格线的模糊观测会被拒绝。
- Unity 桌游模式接收本机识别结果，同步已建棋盘，只预览一次新增的一块房间；确认前改变或遮挡棋盘会取消待确认的建造。继续游戏时须先让实体布局与存档匹配。
- 合成画面和 Unity 模拟输入测试覆盖编号、位置、单块新增与确认流程。这些测试不代表实物识别验收。

## 实体规格与第一轮测试

当前配置假定每格 43 mm，有效 7 × 7 区域为 301 × 301 mm；单块房间标签为 32 × 32 mm，四角定位标签为 20 × 20 mm。相机配置暂以 DJI Osmo Pocket 3、镜头距桌面约 450 mm 为起点，实际高度须根据完整入镜和清晰度调整。400 × 400 mm 底板可以容纳 301 × 301 mm 的有效区域，但应以成品上四角码的内侧角位置为准。

先按 100% 比例打印四角码及 ID 10、ID 11，并实测尺寸。四角码依次放在左上、右上、右下、左下，方向都与画面一致；每张黑白码靠棋盘的内角必须对准 7 × 7 网格的对应外角，不能只居中盖住较大的装饰角标。ID 10 橡树码居中放在中央方块顶面（从左、从上数均为第 4 格）。拍一张只含 ID 10 的原始俯拍画面，再在相邻格加入 ID 11 绿地拍第二张。另拍一段放入 ID 11 并静止至少 2 秒的短视频，以测稳定识别、遮挡和恢复。画面必须同时看见四角码与当前所有房间码。

## 2026-11-06 实机初查

Pocket 3 已被 Windows 识别并拍到 1280 × 720 的完整俯视棋盘。当前实物四角为彩色装饰图案，中央房间顶面为插画，没有印刷的黑白 ArUco 编号码。因此现有识别器在原始帧上检测到 0/4 个定位码，也不能识别中央房间。这是实体标识与已实现识别方案不一致，不能通过调整识别阈值当作已经校准。需要选择：给四角及房间增加可见编号标签并实测，或另行设计和验证插画识别算法。OBS 预览已在检查后恢复。

## 尚待验证与完成

1. 以实际打印件、底板、安装高度和室内光照测量识别率、位置误差及误识率；检查反光、模糊、裁切和遮挡。
2. 实机走通开局同步、逐日新增、非法放置、取消后恢复、旧存档继续，以及相机断开后重新连接。
3. 检查从游戏按钮启动识别器的首次安装体验。当前 `StartCamera.cmd` 需要本机 Python 及首次安装 OpenCV 的网络连接；导出包尚不能视为完全免安装。
4. 实机验收通过后再导出并标记摄像头版。正式参与者测试须另行核对已批准的研究与告知范围。
