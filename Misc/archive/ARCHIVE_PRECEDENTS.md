# Public repository precedents

Reviewed on 20 November 2026 for **organisation**, not for assessment rules or source copying.
These examples do not supersede the supplied IU000293 brief.

| Repository actually read | Observed pattern | Adaptation here |
| --- | --- | --- |
| [Stuart Leitch, Thinking Cap](https://github.com/Toruitas/thinkingcap) | The Creative Computing physical-project log separates `final_code`, intermediate work, hardware material and references; it gives use instructions and expected outputs | Put the current artefact first, distinguish process records from current code, and document a reproducible route into the work |
| [Unity Technologies, Boat Attack](https://github.com/Unity-Technologies/BoatAttack) | README identifies the demo's purpose, Unity/version branches, starting scenes, build steps, credits and untested areas; it warns that ZIPs may omit LFS material | Name the editor/scenes precisely, expose platform limits and credits, and validate that this source ZIP contains asset bytes rather than pointers |
| [The Nature of Code archived p5 examples](https://github.com/nature-of-code/noc-examples-p5.js-archived) | A clear archive banner points to the current examples, while chapter-based examples and historical instructions remain accessible | Keep earlier repositories and rule snapshots available, but state which source is current and which records are historical |

These are descriptive structural lessons, not evidence that a particular layout earns a grade. No project prose, participant
findings, code or visual assets from these examples are passed off as this project's work. Access and source links are retained
in the [reference list](../../Documentation/REFERENCES.md).
