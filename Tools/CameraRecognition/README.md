# SYMBIOSIS: 49 桌游随机抽牌与摄像头识别（原图预览版）

本文件对应 Windows 游戏的**桌游模式**。识别程序使用实体棋盘原有的四角印刷图案定位 7 × 7 网格，并用游戏配套的 80 张房间插画识别已放置方块。正常使用这版程序不需要另贴黑白定位码或房间编号码；`StartArUcoCamera.cmd` 仅供旧版黑白码方案单独使用。

## 启动

1. 保持 `CameraRecognition` 文件夹和 `SYMBIOSIS49-Camera.exe` 在同一层，不要单独移动文件夹内的程序或 `_internal` 文件夹。
2. 将 Pocket 3 设为 Webcam／网络摄像头模式，连接 Windows。固定俯视机位，使棋盘四角印刷图案、完整的 7 × 7 网格和中央橡树方块清楚入镜。
3. 在游戏主菜单进入**桌游模式**，点击游戏里的**启动摄像头**。启动窗口会要求选择摄像头索引 `0–9`；在预览中确认所选画面是棋盘。按 `Q` 或 `Esc` 结束预览。
4. 开局中央橡树使用配套插画 **34 号**，放在第 4 列、第 4 行（程序坐标为 `3,3`）。先完成第 1 天，再按下方“随机抽牌规则”放置方块。保持棋盘静止，待游戏显示识别预览后，在游戏中确认或取消建造。摄像头不会替玩家确认建造。

`StartCamera.cmd` 调用随包提供的 `SYMBIOSIS49-ArtCamera/SYMBIOSIS49-ArtCamera.exe`，使用已训练的 KNN 识别器。运行此打包工具不需要另装 Python 或在线服务。若启动窗口报告找不到原图识别程序，请检查整个 `CameraRecognition/SYMBIOSIS49-ArtCamera` 文件夹是否完整。

## 随机抽牌规则

**图片和库存数量是固定的**：已选定的原图共 80 张，绿地 21、住宅 12、街道 12、广场 11、工作坊 7、垃圾间 7、餐厅 5、超市 5。随机的只是抽取顺序，以及一局最终从中用到的 48 张组合；程序不会随机生成新图片或改变库存。

1. 将中央起始的 34 号橡树从 80 张配套房间方块中取出；其余 **79 张**背面朝上洗匀，作为本局牌池。第 2 天起每天只抽一张，不由玩家挑类别。
2. 将抽到的方块放在棋盘**符合原建造条件**的空格。若当前格不合法，但同一类别在别处仍有合法格，须移动这张方块；不能借此换牌。
3. 只有这张方块所属类别在**整个棋盘上都没有合法格**时，才将它暂放一旁、恢复实体棋盘原状后重抽。后续有了合法位置，可将暂放方块重新混入牌池。
4. 每天在游戏中确认一块方块，结算并进入下一天。49 格填满后，以**动物分＋居民分＝共栖分**结算。本机随机桌游榜先比较**均衡值（动物分与居民分中较低的一项）**，再比较联动分，最后比较共栖分。旧版线性桌游成绩单独显示；开始新局才能使用新规则。

摄像头只能识别画面中的方块类别和位置，**不能证明抽牌是否随机、牌池是否洗匀**。请由现场玩家共同执行抽牌与暂存规则。游戏仍会检查已确认的棋盘、合法位置和每天的建造次数。

## 数据和识别边界

识别工具只向本机 Unity 发送方块位置、类别等识别结果，地址为 UDP `127.0.0.1:49549`；不会通过此连接发送摄像头画面。配套插画与类别的对应关系见 `SYMBIOSIS49-ArtCamera/_internal` 中随包数据；34 号在中央格映射为游戏的开局橡树。

四角或网格未被稳定定位、画面中有占用格却无法识别、或实体棋盘与游戏存档不一致时，游戏会提示问题并暂停新建造。请先调整机位、光照或方块，再根据提示恢复棋盘。已确认的方块不能通过随意移动实体方块来改写游戏布局。

## 当前验证范围

截至 2026-11-06，已用一张真实 Pocket 3 俯视静帧验证四角、网格和中央 34 号橡树；两块及更多房间的组合检查使用的是合成测试画面。实际多块实体棋盘的连续识别、移动和光照变化、摄像头断线重连，以及随机抽牌填满 49 格的完整游玩，仍需现场验收。因此请把本包视为**预览版**，不要把静帧测试结果当作整局可靠性的证明。

开发者测试与识别细节见 `README-art-camera.md`。本目录保留的 `symbiosis49_camera.py`、`StartArUcoCamera.cmd` 和旧版可打印编号码属于黑白码方案，与上述原图版启动流程不同。
